## 3. HEIC in detail (why refusal is right)
- [R] `pillow-heif` is BSD-3-Clause, but its manylinux wheel bundles libheif (LGPL-3.0), libde265 (LGPL-3.0) and x265 (GPL-2.0); the report says its `LICENSES_bundled.txt` calls the whole wheel GPLv2. The reviewer calls the exact version tuple and the "whole wheel GPLv2" conclusion unverified and says to read the file inside the exact wheel; decoder-only builds need not contain x265. Neither changes the verdict.
- [O, mine] Both reports say a server that only returns REST answers does not "convey" LGPL code. That does not help here: DECISIONS J8 says the jury pulls and runs our image, which is distribution. Dynamic linking would then oblige notices, source offer and relinking ability for libheif and libde265, which breaks the project rule (no LGPL in the shipped image).
- [R] No mature permissive HEVC still decoder exists; OpenHEVC is LGPL-2.1; FFmpeg is LGPL-2.1+ (GPL with x265). HEVC also carries patent-pool risk independent of the code licence. Clean option: refuse, message above. Do not offer a sidecar in the 12 hours.

## 4. Safety limits (starting values, all [O]; measure peak RSS before fixing them)
Upload 25 MiB; pages or frames 50; pixels per page 40M, per request 120M; side 20,000 px; ICC 4 MiB, EXIF/XMP/comment 1 MiB in total (check aggregate and before any colour work); render cap 9 MP per PDF page (scale down like the existing `while ... scale > 0.5` loop); ZIP formats: 200 entries, 20 MB per part, 100 MB total expanded, ratio 100:1, no nested archives (reuse `_zip.py` limits); worker wall time 30 s per OCR strip, 120 s per request, kill the whole process tree on timeout and report the page as "not read", never as empty; Tesseract in a subprocess with `OMP_THREAD_LIMIT=1`; at most min(cpus, RAM/200 MB, 4) concurrent OCR processes. Reported planning figure: about 15 bytes per pixel per concurrent job, 58 MB at 200 dpi and 130 MB at 300 dpi [R, OCRmyPDF docs]. Tesseract on huge tables can run for an hour [R], so the hard timeout is a must. pypdfium2 itself recommends a sandbox for hostile PDFs and PDFium has a steady CVE history; keep PDF rendering in a disposable worker.
Local fact [L]: Pillow 13.0.0 is installed here and `Image.MAX_IMAGE_PIXELS` is 89,478,485 (it warns above that, errors above twice that). Report B printed 178,956,970 as the default; that is the error threshold. So the "1024^3/4/3" arithmetic in B is off by the factor of two and B's pixel advice must be read with that in mind.
CVE numbers in B (Pillow 2026-96636, 2026-112403, 2026-112393, 2026-112896; PDFium 2026-17875, 18012, 87585, 93381): unverified by anyone, and the reviewer could not check them. Do not quote them in any document of ours; rely on "Pillow 13.0.0 pinned by hash" and look up advisories in the real tracker when there is time.
The helper code in B keeps every frame as RGB in a list (up to 600 MB at its own limits) and checks metadata per key; do not copy it. Stream page by page.

## 5. What NOT to do
- No second OCR engine in these 12 hours. RapidOCR on onnxruntime with PP-OCRv5 Latin is the only cheap candidate (Polish letters are in its dictionary [R]; code Apache-2.0, ONNX runtime MIT, +45-80 MB estimated), but the realistic cost is 6-7 h not 3-4, it shares the Paddle model family so it adds little diversity, and the `plus` target already exists. Leave it to `plus`.
- No PaddlePaddle, PyTorch, PP-Structure, Surya (weights under a revenue-limited OpenRAIL-M), DocLayout-YOLO (AGPL), LayoutLMv2/v3/XLM (CC-BY-NC-SA), Unstructured (7 GB, LGPL chardet), OCRmyPDF (MPL-2.0 and Ghostscript AGPL), EasyOCR (Torch plus 100 MB). Learned layout models resize the page to 640-1024 px so a 3 mm checkbox shrinks to a few pixels; classic geometry wins on blank forms [O]. Only a nano form-field model (0.9 M parameters, 3.7 MB, Apache-2.0 per A) is worth a later A/B, not now.
- No `opencv-python(-headless)` into core: no Alpine wheel, and the reviewer notes the wheel bundles LGPL FFmpeg. That also rules out OpenCV perspective correction of phone photos in core: for photos refuse with "The whole sheet is not visible; include all four corners on a contrasting background" when the page edge is not found by a pure-Pillow test, or leave it to `plus`.
- No global grey-vs-binary, `pol`-only, Sauvola, CLAHE, median or NL-means change without the row 5 test (a 9x9 median dropped one clean page from 98.9 % to 91.0 % [R]; heavy filters erase Polish dots and ogoneks).
- No `tessedit_char_whitelist` on whole pages; only on isolated numeric crops, and retry without it if the result is empty. No LibreOffice, FFmpeg or Pandoc in core.
- No silent first frame of an animated file, no text-only RTF presented as a converted form.
